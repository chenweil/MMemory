# C3阶段智能降级机制使用指南

## 概述

C3阶段实现了基于AI Provider智能选择的降级机制，通过多维度评分、成本控制、趋势分析等技术，实现最优的AI服务选择和降级策略。

### 核心组件说明

#### 1. IntelligentManager (智能管理器)
- **功能**: 基于多维度评分选择最优Provider
- **评分维度**:
  - Performance (性能): 响应时间评分，越快越高分
  - Reliability (可靠性): 成功率评分
  - Cost (成本): 基于使用成本的评分
- **策略权重**: 可配置性能、可靠性、成本的权重

#### 2. CostController (成本控制器)
- **功能**: 预算管理和成本追踪
- **特性**:
  - 月度预算设置和追踪
  - 实时成本记录
  - 预算阈值告警
  - 成本优化建议

#### 3. StrategyEngine (策略引擎)
- **功能**: 可配置的降级决策
- **降级条件**:
  - 响应时间超过阈值
  - 错误率超过阈值
  - 成本预算超限
  - Provider不可用

#### 4. AdvancedMonitor (高级监控)
- **功能**: 趋势分析和告警
- **监控指标**:
  - Provider响应时间趋势
  - 错误率趋势
  - 决策延迟
  - 降级原因统计

## 使用方法

### 1. 基础使用

```go
package main

import (
    "context"
    "log"

    "mmemory/pkg/ai"
)

func main() {
    // 1. 创建Provider
    openaiProvider, err := ai.NewOpenAIProvider(ai.ProviderConfig{
        APIKey:    "your-openai-api-key",
        Model:     "gpt-4o-mini",
        MaxTokens: 1000,
        Timeout:   30 * time.Second,
    })
    if err != nil {
        log.Fatal(err)
    }

    // 2. 创建C3集成
    providers := map[string]ai.AIProviderInterface{
        "openai": openaiProvider,
    }

    c3Config := ai.C3Config{
        Strategy: ai.FallbackStrategy{
            MaxResponseTime:     10 * time.Second,
            ErrorRateThreshold:  0.15,
            CostWeight:         0.3,
            PerformanceWeight:  0.4,
            ReliabilityWeight:  0.3,
        },
        Budget: ai.BudgetConfig{
            MonthlyBudget:   100.0,
            AlertThreshold:  0.8,
            ResetDay:        1,
        },
        Providers: map[string]*ai.ProviderCost{
            "openai": {
                CostPer1KTokens: 0.0015,
                Model:          "gpt-4o-mini",
                Provider:       "openai",
            },
        },
        Monitoring: ai.MonitoringConfig{
            AdvancedEnabled: true,
        },
    }

    c3Integration, err := ai.NewC3Integration(
        providers,
        "openai",
        []string{},
        c3Config,
        log.New(os.Stdout, "", log.LstdFlags),
    )
    if err != nil {
        log.Fatal(err)
    }

    // 3. 使用智能解析
    ctx := context.Background()
    result, err := c3Integration.ParseWithIntelligentC3(ctx, "明天早上9点提醒我开会")
    if err != nil {
        log.Fatal(err)
    }

    log.Printf("解析结果: %+v", result)
}
```

### 4. 动态调整策略

```go
// 根据使用情况动态调整策略
func adjustStrategy(c3 *ai.C3Integration) {
    stats := c3.GetC3Stats()

    // 如果成本使用率过高，增加成本权重
    if costReport, ok := stats["cost_report"].(*ai.CostReport); ok {
        if costReport.Budget.UsageRate > 0.8 {
            c3.UpdateStrategy(ai.FallbackStrategy{
                CostWeight:         0.5,
                PerformanceWeight:  0.3,
                ReliabilityWeight:  0.2,
            })
            log.Info("已调整为成本优先策略")
        }
    }
}
```

## 最佳实践

### 1. 策略配置建议

#### 平衡型 (推荐用于生产环境)
```yaml
strategy:
  cost_weight: 0.3          # 成本占30%
  performance_weight: 0.4   # 性能占40%
  reliability_weight: 0.3   # 可靠性占30%
```

#### 成本优先型 (预算紧张时)
```yaml
strategy:
  cost_weight: 0.6          # 成本占60%
  performance_weight: 0.2   # 性能占20%
  reliability_weight: 0.2   # 可靠性占20%
```

#### 性能优先型 (对响应时间敏感)
```yaml
strategy:
  cost_weight: 0.2          # 成本占20%
  performance_weight: 0.6   # 性能占60%
  reliability_weight: 0.2   # 可靠性占20%
```

### 2. 成本控制建议

1. **设置合理的月预算**
   - 根据业务需求设置月度预算
   - 建议保留20%缓冲

2. **配置告警阈值**
   - 80%时发送预警
   - 90%时发送严重告警
   - 100%时触发强制降级

3. **定期查看成本报告**
   - 每日查看使用情况
   - 每周分析成本趋势
   - 每月生成详细报告

### 3. 监控建议

1. **关键指标**
   - Provider响应时间趋势
   - 错误率变化
   - 成本使用率
   - 降级触发频率

2. **告警设置**
   - 响应时间超过5秒
   - 错误率超过15%
   - 成本使用率超过90%
   - 连续3次降级

## 监控指标

### Prometheus指标

C3系统提供以下Prometheus指标：

1. **ai_provider_response_trend** - Provider响应时间趋势
   - 标签: `provider`
   - 类型: Gauge
   - 说明: 0-100分数，50表示稳定

2. **ai_provider_error_rate_trend** - Provider错误率趋势
   - 标签: `provider`
   - 类型: Gauge
   - 说明: 0-1之间的错误率

3. **ai_cost_budget_usage** - 成本预算使用率
   - 标签: `budget`
   - 类型: Gauge
   - 说明: 0-1之间的使用率

4. **ai_decision_latency_seconds** - 决策延迟
   - 标签: `decision_type`
   - 类型: Histogram
   - 说明: Provider选择的决策时间

5. **ai_fallback_reasons_total** - 降级原因统计
   - 标签: `reason`
   - 类型: Counter
   - 说明: 各种降级原因的触发次数

## 常见问题

### Q1: 如何选择合适的策略权重？

**A**: 根据业务需求选择：
- **平衡型**: 适合大多数场景
- **成本优先**: 预算有限时
- **性能优先**: 响应时间敏感的业务

### Q2: 预算超限后系统如何处理？

**A**: 系统会：
1. 发送告警通知
2. 自动调整策略权重
3. 优先选择低成本Provider
4. 可以配置强制停止策略

### Q3: 如何优化成本？

**A**: 建议：
1. 监控成本报告，找到高成本Provider
2. 优化Prompt，减少token使用
3. 使用缓存避免重复请求
4. 考虑使用更经济的模型

### Q4: 熔断器如何工作？

**A**: 熔断器有三种状态：
- **Closed**: 正常状态，请求正常通过
- **Open**: 熔断状态，直接拒绝请求
- **Half-Open**: 半开状态，尝试放行少量请求

触发条件：
- 连续5次请求失败
- 错误率超过50%
- 自动恢复时间30秒

### Q5: 如何实现Provider的自动切换？

**A**: 系统自动处理：
1. 监控Provider健康状态
2. 响应时间超过阈值时降级
3. 错误率过高时熔断
4. 成本超限时切换到低成本Provider
