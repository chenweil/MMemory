# C6-用户生活记录系统需求文档

**文档版本**: v1.0
**创建日期**: 2025-12-30
**状态**: 待实现

---

## 1. 背景与目标

### 1.1 背景
当前 MMemory 系统主要专注于提醒功能，但缺乏对用户日常活动的记录和追踪能力。用户在对话中会提到各种生活细节（如喝水、吃药、看书等），这些信息目前没有被系统化地记录和利用。

### 1.2 目标
创建一个用户生活记录系统，用于：
1. 记录用户的日常活动（喝水、吃药、看书、运动等）
2. 从对话中自动提取和记录活动信息
3. 支持主动关怀，询问用户活动情况
4. 为后续的统计分析和智能建议提供数据基础

## 2. 核心功能需求

### 2.1 活动记录功能

#### 2.1.1 支持的活动类型
- **健康类**: 喝水、吃药、运动、睡眠
- **学习类**: 看书、学习、听课
- **生活类**: 吃饭、购物、家务
- **自定义**: 用户可自定义活动类型

#### 2.1.2 记录的信息字段
```go
type DailyActivity struct {
    ID          uint
    UserID      uint
    ActivityType string      // 活动类型: "喝水", "吃药", "看书" 等
    OccurredAt  time.Time    // 发生时间
    Details     string       // 详细信息（JSON 格式）
    Source      string       // 记录来源: "conversation", "manual", "reminder"
    Metadata    string       // 元数据（JSON 格式）
    CreatedAt   time.Time
}
```

**Details 字段示例**:
- 喝水: `{"amount": "200ml", "type": "温水"}`
- 吃药: `{"medicine_name": "阿莫西林", "dosage": "1粒", "frequency": "每日3次"}`
- 看书: `{"book_name": "如何阅读一本书", "chapter": "第十一章", "page": "150"}`
- 运动: `{"type": "跑步", "duration": "30分钟", "distance": "5公里"}`

### 2.2 AI 智能提取

#### 2.2.1 从对话中提取活动信息
当用户在对话中提到活动时，AI 应该自动识别并记录：

**示例对话**:
```
用户: "我刚才喝了杯水"
→ 系统记录: ActivityType="喝水", Details={"amount": "1杯"}

用户: "我正在看《如何阅读一本书》，读到第十一章了"
→ 系统记录: ActivityType="看书", Details={"book_name": "如何阅读一本书", "chapter": "第十一章"}

用户: "今天吃了阿莫西林"
→ 系统记录: ActivityType="吃药", Details={"medicine_name": "阿莫西林"}
```

#### 2.2.2 AI 解析能力扩展
需要在现有的 AI 解析服务中添加新的意图：
- `IntentRecordActivity` - 记录活动意图
- `IntentQueryActivity` - 查询活动记录意图
- `IntentActivitySummary` - 活动统计意图

### 2.3 主动关怀功能

#### 2.3.1 基于提醒的主动询问
当提醒触发时，如果与某个活动类型相关，可以主动询问详细情况：

**示例场景**:
```
提醒: "该喝水了"
用户点击"完成了"
→ 系统追问: "喝了多少？温水还是凉水？"
→ 用户回复: "300ml温水"
→ 系统记录活动详情
```

#### 2.3.2 定期关怀
系统可以定期（如每天晚上）主动询问用户的活动情况：

**示例对话**:
```
系统: "今天看了什么书？读到哪一章了？"
用户: "看了《如何阅读一本书》，读到第十二章了"
→ 系统记录活动
```

### 2.4 查询与统计功能

#### 2.4.1 查询活动记录
用户可以查询历史活动记录：

**示例对话**:
```
用户: "我最近看过哪些书？"
系统: "根据记录，你最近看了：
- 《如何阅读一本书》（读到第十一章）
- 《深入理解计算机系统》（读到第5章）
"

用户: "我昨天喝水了吗？"
系统: "昨天你记录了 5 次喝水，总共约 1000ml"
```

#### 2.4.2 统计分析
支持生成活动统计报告：

**示例对话**:
```
用户: "这周我看了多少书？"
系统: "本周你看了 3 本书，累计阅读时间约 5 小时"
```

## 3. 技术设计

### 3.1 数据库设计

#### 3.1.1 新增表: daily_activities
```sql
CREATE TABLE `daily_activities` (
  `id` integer PRIMARY KEY AUTOINCREMENT,
  `user_id` integer NOT NULL,
  `activity_type` text NOT NULL,        -- 活动类型: "喝水", "吃药", "看书" 等
  `occurred_at` datetime NOT NULL,       -- 发生时间
  `details` text,                        -- 详细信息 (JSON)
  `source` text NOT NULL DEFAULT 'conversation', -- 记录来源
  `metadata` text,                       -- 元数据 (JSON)
  `created_at` datetime NOT NULL,
  FOREIGN KEY (`user_id`) REFERENCES `users`(`id`)
);

CREATE INDEX idx_daily_activities_user_id ON daily_activities(user_id);
CREATE INDEX idx_daily_activities_type ON daily_activities(activity_type);
CREATE INDEX idx_daily_activities_occurred_at ON daily_activities(occurred_at);
CREATE INDEX idx_daily_activities_user_time ON daily_activities(user_id, occurred_at DESC);
```

#### 3.1.2 新增表: activity_types（可选，用于管理活动类型）
```sql
CREATE TABLE `activity_types` (
  `id` integer PRIMARY KEY AUTOINCREMENT,
  `name` text NOT NULL UNIQUE,
  `category` text NOT NULL,              -- 分类: "health", "learning", "life"
  `icon` text,                           -- 图标
  `color` text,                          -- 显示颜色
  `is_active` numeric DEFAULT true,
  `created_at` datetime NOT NULL
);
```

### 3.3 AI Prompt 设计

#### 3.3.1 活动识别 Prompt
在现有的 `ReminderParse` Prompt 中添加活动记录识别能力：

```
## 活动记录识别

当用户提到以下活动时，请识别为 record_activity 意图：
- 喝水: "我喝了水", "刚喝了杯水", "今天喝了3杯水"
- 吃药: "吃了药", "今天吃了阿莫西林", "刚吃过药"
- 看书: "正在看书", "读了第十一章", "看了《如何阅读一本书》"
- 运动: "跑了5公里", "健身了", "跳绳30分钟"

提取以下信息：
- activity_type: 活动类型（喝水、吃药、看书、运动等）
- details: 详细信息（JSON 格式）
  - 喝水: amount, type
  - 吃药: medicine_name, dosage, frequency
  - 看书: book_name, chapter, page
  - 运动: type, duration, distance
```

#### 3.3.2 活动查询 Prompt
```
## 活动查询识别

当用户查询活动记录时，请识别为 query_activity 意图：
- "我看过哪些书？"
- "昨天喝水了吗？"
- "最近运动了多少次？"
- "这周看了多少书？"

提取以下信息：
- query_type: 查询类型（按类型、按时间、按统计）
- activity_type: 活动类型（可选）
- time_range: 时间范围（最近7天、昨天、今天等）
```

### 3.4 数据流程

#### 3.4.1 活动记录流程
```
用户发送消息
  ↓
MessageHandler.handleTextMessage
  ↓
AIParserService.ParseMessageWithContext
  ↓
FallbackChain.ParseWithContext
  ↓
OpenAI Client (识别为 record_activity 意向)
  ↓
ParseResult { Intent: record_activity, Activity: {...} }
  ↓
handleRecordActivityIntent
  ↓
DailyActivityService.RecordActivity
  ↓
保存到 daily_activities 表
  ↓
发送确认消息给用户
```

#### 3.4.2 主动关怀流程
```
提醒触发（如"该喝水了"）
  ↓
用户点击"完成了"
  ↓
NotificationService.SendFollowUp（增强版）
  ↓
检查是否有活动详情记录
  ↓
如果无详情 → 主动询问："喝了多少？"
  ↓
用户回复详情
  ↓
更新活动记录（添加 details）
```

## 5. 非功能性需求

### 5.1 性能
- 活动记录查询响应时间 < 500ms
- 支持单用户 10,000+ 条活动记录
- 统计查询响应时间 < 1s

### 5.2 数据保留
- 活动记录默认保留 1 年
- 支持用户手动删除历史记录
- 提供数据导出功能（可选）

### 5.3 隐私和安全
- 活动记录仅用户本人可访问
- 支持数据脱敏导出
- 符合 GDPR 等隐私法规（如适用）

## 7. 风险和挑战

### 7.1 AI 解析准确性
- **风险**: AI 可能无法准确提取活动信息
- **缓解**: 提供手动修正功能，持续优化 Prompt

### 7.2 数据隐私
- **风险**: 用户可能担心活动记录的隐私
- **缓解**: 明确隐私政策，提供数据删除选项

### 7.3 用户体验
- **风险**: 过多主动询问可能打扰用户
- **缓解**: 提供关怀频率设置，支持用户自定义

- 用户主动使用率 > 60%
