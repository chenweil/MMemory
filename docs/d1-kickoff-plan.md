# D1 智能提醒建议启动计划 [[D]]

## 🎯 项目目标 [[D]]
- 利用用户历史行为与上下文信息，提供 3-5 条高价值提醒建议。
- 提升提醒采纳率，目标建议点击率 > 40%，新增提醒中 30% 来自建议创建。
- 保持生成延迟 < 500ms，并记录可观测指标支持持续迭代。

## 📥 输入准备 [[D]]
- **上下文数据**：通过 D2 `ContextManager` 获取最近意图、状态、实体和对话摘要。
- **行为数据**：从提醒/日志仓库加载活跃时段、响应率、延期统计、常用提醒类型。
- **用户配置**：读取个人偏好（提醒频率、静默时段、语言）作为筛选项。
- **系统配置**：在 `configs/config.yaml` 中新增 `suggestion` 相关阈值（采样窗口、响应率下限等）。

## 🗄️ 数据准备 [[D]]
- 扩展 `reminder_logs` 查询，支持：
  - 计算活跃时间段（按小时、星期聚合）。
  - 统计完成率、延期率、平均延期分钟数。
  - 提取常见提醒主题关键词。
- 视性能需求引入 `user_behavior_stats` 视图或缓存表，定期刷新。
- 确保与 D2 实体字段命名一致（如 `task`, `datetime`, `recurrence`）。

## 🏗️ 服务架构 [[D]]
- 新建 `ReminderSuggestionService`，职责包括：
  - 封装建议生成主流程 (`GenerateSuggestions(ctx, userID, context string)`).
  - 组合 `UserBehaviorAnalyzer`、`ContextAnalyzer`、`SuggestionRanker`。
  - 提供可监控的指标输出（生成耗时、命中率、过滤比率）。
- 定义接口：
  - `UserBehaviorRepository`：提供历史数据查询方法。
  - `SuggestionCache`（可选）：缓存近期建议，避免重复推送。
  - `NotificationAdapter`：负责将建议以 Bot 消息形式推送。

## 🧠 算法 MVP [[D]]
- 采用规则 + 统计评分策略：
  - 基于活跃时段与响应率筛选候选时间。
  - 使用关键词匹配与上下文意图确定建议类型（习惯/任务/时间优化）。
  - 为每条建议计算综合得分（响应率权重、上下文匹配度、去重惩罚）。
- 生成 3-5 条候选项，带有：
  - 标题（任务/习惯名称）。
  - 建议时间与频率。
  - 理由标签（例如“最近完成率 92%”“晚间更易完成”）。
- 预留扩展点：未来可替换为 ML 模型或 AI 生成文案。

## 🤖 Bot 交互设计 [[D]]
- 触发规则：
  - 用户主动询问（如“有什么建议”）。
  - 对话空闲时段（无提醒创建成功的 24 小时后提示一次）。
  - 完成提醒或延迟后，基于上下文给出后续建议。
- 消息模板：
  - 主动建议消息 + Inline Keyboard 快速创建按钮。
  - 提供“换一批”“关闭建议”操作。
- Handler 流程：
  - `suggestion_handler` 接收触发信号 → 调用 `ReminderSuggestionService`.
  - 解析用户操作反馈（接受/忽略/关闭）并写入统计。

## 🧪 测试与验证 [[D]]
- 单元测试覆盖：
  - 行为分析统计方法（边界与缺失数据）。
  - 建议生成逻辑（避免重复、得分排序、阈值过滤）。
  - Bot 交互流程（模拟 Inline Callback）。
- 指标验证：
  - 仿真数据集，验证建议时间落在活跃区间 ≥ 80%。
  - 建议命中率、重复率（需埋点记录）。

## 📅 里程碑与依赖 [[D]]
1. **Week 1**：完成数据接口与服务骨架；编写基本单元测试。
2. **Week 2**：集成 Bot 流程与建议模板；接入监控指标。
3. **Week 3**：A/B 测试与调优（若时间允许），准备 D3 个性化扩展需求。
- 依赖：D2 MVP 提供稳定上下文接口；提醒/日志仓库暴露统计查询。
