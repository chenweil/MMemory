# 变更提案：修复 Bot 客户端超时配置冲突

## 变更 ID
fix-bot-client-timeout-configuration

## 变更类型
Bug Fix

## 优先级
High

## 问题描述

当前 MMemory Bot 在运行时频繁出现 Telegram API 连接超时错误，导致大量重试日志刷屏。具体表现为：

1. **频繁超时错误**：
   - `context deadline exceeded (Client.Timeout exceeded while awaiting headers)`
   - `unexpected EOF`

2. **配置冲突**：
   - `internal/bot/client.go` 中定义的自定义 HTTP 客户端配置了 120 秒总超时
   - 但 `cmd/bot/main.go` 中 `GetUpdatesChan` 的超时设置只有 30 秒
   - 30 秒超时会覆盖 HTTP 客户端的 120 秒超时配置

3. **重试逻辑问题**：
   - 没有重试间隔控制
   - 短时间内大量重试导致日志刷屏

## 根本原因分析

1. **超时时间过短**：30 秒的超时在网络不稳定时容易触发，特别是在中国大陆访问 Telegram API 时
2. **配置不一致**：HTTP 客户端和 GetUpdatesChan 的超时配置不匹配
3. **错误处理不完善**：没有区分临时错误和致命错误，导致所有错误都触发重试

## 影响范围

- **影响模块**：`cmd/bot/main.go`, `internal/bot/client.go`
- **影响功能**：Telegram Bot 消息接收和更新处理
- **用户体验**：频繁的重试日志影响日志可读性，可能影响 Bot 响应速度

## 解决方案

### 1. 增加 GetUpdatesChan 超时时间
- 从 30 秒增加到 60-90 秒
- 与 HTTP 客户端的 120 秒总超时保持合理比例

### 2. 优化重试间隔
- 实现指数退避重试策略
- 避免短时间内大量重试
- 控制重试日志输出频率

### 3. 改进错误处理
- 区分临时错误（网络波动）和致命错误（配置错误）
- 对临时错误使用退避重试
- 对致命错误快速失败并记录详细日志

### 4. 添加连接健康检查
- 定期检测 Bot 连接状态
- 连接异常时自动重建连接

## 预期效果

1. **减少超时错误**：通过增加超时时间，降低网络波动导致的超时
2. **优化日志输出**：通过退避重试，避免日志刷屏
3. **提高稳定性**：通过改进错误处理，提高 Bot 整体稳定性
4. **更好的用户体验**：减少因连接问题导致的消息接收延迟
